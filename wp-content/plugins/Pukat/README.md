## Architecture

```
WordPress Plugin (Pukat)
├── PHP Backend (REST API proxy + DB)
│   ├── REST controllers: includes/Api/
│   ├── business logic: includes/Services/
│   ├── database access: includes/Repositories/
│   └── communicates with GoPhish via wp_remote_* (HTTP)
└── React Frontend (SPA in WP Admin + /pukat)
    └── calls: wp-json/pukat/v1/*
                    ↓
            GoPhish REST API
            (remote server, API key never in browser)
```

## Project Structure

```
Pukat/
├── pukat.php                 # Main WordPress plugin entry point
├── uninstall.php             # Full cleanup when the plugin is deleted
├── composer.json             # PHP autoload configuration
├── README.md
├── assets/
│   └── dist/                 # Production React/Vite build consumed by WordPress
├── docs/
│   ├── pukat.md              # Product requirements / module notes
│   └── prototypes/           # Legacy static prototypes and UI snippets
├── includes/
│   ├── Api/                  # REST controllers only
│   ├── Core/                 # Plugin bootstrap, activation, deactivation
│   ├── Admin/                # WP Admin menu and admin SPA shell
│   ├── Frontend/             # /pukat frontend SPA route and shell
│   ├── Services/             # Business logic, shared context, assets, integrations
│   └── Repositories/         # Database access logic
└── pukat-app/                # React/Vite source application
    └── src/
        ├── api/              # Frontend REST API clients, split by domain
        ├── components/       # Shared UI/layout components
        ├── features/         # Feature-based frontend modules
        ├── pages/            # Route-level pages not yet feature-split
        └── store/            # Global Zustand store
```

`pukat-app/` is source code for development. WordPress does not load files from
`pukat-app/src`; it loads the built bundle from `assets/dist/` using the Vite
manifest generated by `npm run build`.

## Requirements

- PHP 8.1+
- WordPress 6.0+
- MySQL 5.7+ / MariaDB 10.3+
- Node.js 18+ (for building the React app, dev only)
- GoPhish instance (remote server)

## Installation

### 1. Upload Plugin
```bash
# Copy to wp-content/plugins/
cp -r Pukat/ /path/to/wordpress/wp-content/plugins/
```

### 2. Build React App
```bash
cd Pukat/pukat-app
npm install
npm run build
# Builds to ../assets/dist/
```

### 3. Install PHP Dependencies (optional, uses manual autoloader if skipped)
```bash
cd Pukat/
composer install --no-dev --optimize-autoloader
```

### 4. Activate in WordPress
Go to **Plugins → Activate** for **Pukat — Phishing Simulation Platform**.

### 5. Configure GoPhish Connection
1. Go to **Pukat → Settings**
2. Enter your GoPhish API URL (e.g. `https://your-server:3333`)
3. Enter your GoPhish API Key (found in GoPhish → Account Settings)
4. Click **Test Connection**
5. Click **Save Settings**

## Development

```bash
# Start Vite dev server (proxies to WP)
cd pukat-app/
npm run dev
```

Edit `vite.config.js` to set the correct WP URL for the proxy.

Production builds are written to `assets/dist/`:

```bash
cd pukat-app/
npm run build
```

The frontend API modules are split by domain, for example
`src/api/campaignApi.js`, `src/api/playbookApi.js`, and
`src/api/settingsApi.js`. `src/api/index.js` remains an export aggregator so
existing imports such as `import { campaignApi } from '../../api/index.js'`
continue to work.

## REST API

Base URL: `/wp-json/pukat/v1/`

All endpoints require a valid WP session with appropriate Pukat role.

| Method | Endpoint | Auth Required |
|--------|----------|---------------|
| GET | `/gophish/status` | Admin |
| GET | `/gophish/templates/email` | Operator+ |
| GET | `/gophish/templates/landing` | Operator+ |
| GET | `/gophish/smtp` | Operator+ |
| GET/POST | `/campaigns` | Read / Operator |
| GET/DELETE | `/campaigns/{id}` | Read / Operator |
| POST | `/campaigns/{id}/launch` | Operator |
| POST | `/campaigns/{id}/complete` | Operator |
| GET | `/campaigns/{id}/results` | Read |
| GET/POST | `/playbooks` | Read / Operator |
| GET/POST | `/quiz/questions` | Operator |
| POST | `/quiz/submit` | Public |
| GET | `/reports/{campaign_id}` | Read |
| GET | `/risk-scores` | Read |
| GET/PUT | `/settings` | Admin |
| GET | `/users` | Admin |
| PUT | `/users/{id}/role` | Admin |
| GET | `/audit-logs` | Admin |

## Database Tables

All tables prefixed with `{wp_prefix}pukat_`:

| Table | Purpose |
|-------|---------|
| `campaigns` | Mirror + metadata for GoPhish campaigns |
| `targets` | Target list per campaign |
| `playbooks` | Reusable campaign configurations |
| `quiz_questions` | Question bank |
| `quiz_results` | Quiz answers + scores per target |
| `risk_scores` | Risk scores per target (historical) |
| `coaching_assignments` | Training assignments |
| `socialization_logs` | Email delivery tracking |
| `audit_logs` | Immutable action audit trail |

## Security

- GoPhish API key stored **AES-256-GCM encrypted** in `wp_options`
- API key **never exposed** to browser — all GoPhish calls proxied via PHP
- WP nonce enforced on all REST endpoints
- Role-based access: `pukat_admin` | `pukat_operator` | `pukat_viewer`
- Audit log for all significant actions
